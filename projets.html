01 — Projets Académiques Personnels R&D

Tous mes projets.

Académiques (SAÉ, brevets, BUT) et personnels — cliquez sur un projet pour voir le détail.

Contexte — ATLAS (Assistance Temps-réel aux Laboratoires et Activités de Séquençage) est la plateforme de la division de biologie médicale de l'AP-HP Henri Mondor, projet GenoBioMICS (accrédité COFRAC 15189 et 17025). Elle gère le cycle NGS complet : dépôt des prélèvements → pipeline séquençage → rapport clinique, avec traçabilité réglementaire exhaustive. Je suis le seul développeur de la stack applicative.

A — Backend Go (BFF)

Architecture microservices

  • Pattern BFF (Backend-For-Frontend) en Go — point d'entrée unique : auth OIDC, sessions HTTPOnly, permissions, orchestration
  • OIDC + PKCE avec Zitadel — échange code→tokens, validation JWT à chaque requête, refresh transparent
  • ReBAC via SpiceDB (gRPC) — droits dérivés du graphe de relations (groupes, propriétés, rôles)
  • PBAC via OPA — politiques Rego contextuelles (statut ressource, rôle, heure)
  • Observabilité Redis — présence (heartbeat TTL 5min), métriques 7j, alertes seuils CPU/MEM/NET
  • Pipeline pré-inscription : formulaire multi-étapes → upload SeaweedFS → validation admin → création compte Zitadel → activation
B — Frontend React/TypeScript

SPA 30+ pages

  • React 19 + Vite 7 + TypeScript — SPA avec React Router v7, TanStack Query v5 (cache serveur)
  • Portail utilisateur : habilitations, stock réactifs, demandes d'analyse, lots de séquençage, prescripteurs, parc machines
  • Dashboard admin temps réel : observabilité (CPU/MEM/réseau), sessions actives, gestion utilisateurs, matrice permissions
  • Visualisation graphe applicatif via @xyflow/react — carte des 30+ services et leurs dépendances
  • Module PDF Vanesa : extraction LLM de documents cliniques, stockage PostgreSQL + SeaweedFS
C — Infrastructure Kubernetes

Production OVH

  • Kubernetes v1.31 sur Rocky Linux 10 OVH — single-node control-plane, ~70 pods en prod
  • ArgoCD GitOps — 14 applications, sync automatique depuis GitLab à chaque commit main
  • Helm (GitLab CE, kube-prometheus-stack, cert-manager, ingress-nginx, Nautobot) + Kustomize (hermes, gitops)
  • cert-manager + Let's Encrypt — TLS auto sur *.atlasaphp.duckdns.org
  • Vault / OpenBao — injection secrets via agent sidecar, authentification ServiceAccount K8s
  • NetworkPolicies Zero Trust — default-deny sur tous les namespaces, ouvertures explicites par service
D — DataHouse & Services

Données génomiques

  • Dgraph v25 — graphe métier hospitalier (Personne, Emploi, Unité, Run NGS, Documents)
  • Iceberg + Nessie + Trino — DataHouse à 3 couches : Bronze (FASTQ bruts) → Silver (variants annotés) → Gold (prêt IA)
  • DuckDB — ETL Bronze→Gold (Python), transformations locales ultra-rapides
  • SeaweedFS — stockage S3-compatible (pièces jointes, artifacts NGS, tables Iceberg)
  • Nautobot — CMDB réseau/infra (source of truth des équipements et services)
  • Zitadel SSO étendu — GitLab, ArgoCD, Grafana, Nautobot authentifiés via OIDC centralisé
E — Sécurité & Hardening

Zero Trust

  • firewalld zone DROP — seuls SSH/80/443 ouverts vers l'extérieur
  • fail2ban SSH — ban 48h après 3 tentatives, intégré avec firewalld rich-rules
  • SSH durci : AllowUsers rocky, PermitRootLogin no, MaxAuthTries 3, clé ED25519 uniquement
  • SPIRE — identités cryptographiques x.509 (SVIDs) pour les workloads K8s (mTLS inter-services)
  • Protections kernel sysctl — anti-spoofing, SYN-flood, ICMP broadcast, redirections désactivées
F — Observabilité

Stack monitoring

  • kube-prometheus-stack — Prometheus + Grafana + Alertmanager, scrape complet K8s
  • Loki + Promtail — agrégation et recherche des logs de tous les pods
  • Grafana SSO — authentification Zitadel OIDC, dashboards CPU/MEM/réseau par namespace
  • Nautobot — ITSM et inventory (tickets, IP, VLAN, équipements)
  • kube-state-metrics — état des objets K8s (Deployments, PVCs, Pods) exposé à Prometheus

A — Architecture ML

Mixture of Experts multitâche

  • Backbone partagé EfficientNetB0 (ImageNet) + GlobalAvgPool + BN + Dropout
  • 3 têtes MoE indépendantes — âge (régression), genre (sigmoid), ethnie (softmax 5 classes)
  • Chaque tête : 4 experts MLP + gating network softmax qui route dynamiquement l'image
  • Focal Loss sur l'ethnie pour corriger le déséquilibre de classes
  • Entraînement 3 phases : warmup backbone gelé → fine-tune partiel (BN gelé) → fine-tune complet
  • Mixed precision float16 — réduit la mémoire GPU et accélère le train
  • Comparaison de 4 backbones (EfficientNetB0 retenu sur rapport précision/taille)

C — Évaluation

Métriques par tâche

  • Régression âge — MAE (erreur en années), MSE, R²
  • Classification genre — Accuracy, AUC, Average Precision
  • Classification ethnie — Accuracy, AUC, AP, ARI, NMI
  • Visualisation Grad-CAM — zones activées par le modèle
  • Dataset UTKFace : 23 708 images (âge 0–116, 2 genres, 5 ethnies)
D — 3 stratégies comparées

Approche comparative

  • Strat. 1 — 3 modèles spécialisés entraînés indépendamment
  • Strat. 2 — Modèle MoE multitâche (architecture retenue)
  • Strat. 3 — Ablation study sur 4 backbones CNN
  • Objectif : valider l'apport du partage de représentation entre tâches
